## ADDED Requirements

### Requirement: Releases SHALL flag incompatible operator migrations
When an upgrade contains a changed or removed configuration contract that prevents existing installations from starting without manual action, the release SHALL prominently identify it as a breaking change before generic generated release notes. The operator instructions SHALL identify affected configurations, pre-upgrade actions, post-upgrade verification and rollback.

#### Scenario: Breaking change in standalone upgrade note
- **WHEN** a release introduces a new operator note containing the `**Breaking Change:**` marker
- **THEN** the published release body begins with a visible `BREAKING CHANGE` heading before the autogenerated changelog
- **AND** it retains the full operator instructions and original changelog

#### Scenario: Nonbreaking upgrade note
- **WHEN** a release contains only ordinary operator notes without a breaking-change marker
- **THEN** the publisher retains the conventional important-upgrade heading rather than falsely marking a breaking change

#### Scenario: Keycloak migration before version 1.6.0
- **WHEN** the Keycloak self-registration migration is released
- **THEN** the required note names the removed Keycloak provider configuration, realm setup, SMTP confirmation and rollback
- **AND** the release checklist requires an operator smoke-test before the release is considered production-ready
