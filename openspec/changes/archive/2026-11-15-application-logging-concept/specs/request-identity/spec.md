## ADDED Requirements

### Requirement: Request ID is accepted only from trusted proxies and validated
The backend SHALL assign exactly one `request_id` per HTTP request. It SHALL use the `X-Request-ID` header only when the TCP peer lies in `TRUSTED_PROXIES` (same rule and helper as the client IP) and the value matches `^[A-Za-z0-9-]{1,64}$`; otherwise it SHALL generate a UUID. An invalid header SHALL NOT fail the request.

#### Scenario: Client-supplied ID from an untrusted peer
- **WHEN** a peer outside `TRUSTED_PROXIES` sends `X-Request-ID`
- **THEN** a fresh UUID is used instead of the header value

#### Scenario: ID from the trusted frontend nginx
- **WHEN** the frontend nginx forwards a request with its generated `X-Request-ID`
- **THEN** that ID is used as the request's `request_id`

#### Scenario: Oversized or malformed ID from a trusted peer
- **WHEN** a trusted peer sends an `X-Request-ID` longer than 64 characters or containing a newline, quote or space
- **THEN** a fresh UUID is used and the request is processed normally

### Requirement: Frontend nginx generates the request ID
The frontend nginx SHALL set `X-Request-ID` to its own `$request_id` on every request proxied to the backend and SHALL NOT forward a client- or upstream-supplied `X-Request-ID`.

#### Scenario: Client tries to choose the request ID
- **WHEN** a browser or the external TLS proxy sends `X-Request-ID: attacker-chosen`
- **THEN** the backend receives the ID generated by the frontend nginx instead
